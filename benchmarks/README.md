# Agent benchmark

Run the benchmark in the conversation the user chooses. A fresh conversation gives each model a similar starting context, but is optional.

1. Use a fresh MCP session. Answer the eight questions in [cases.json](cases.json) **sequentially, in file order**. For each: `search_catalog` → `get_metadata` → `retrieve` → read the saved JSON → answer with a source citation. Use only the MCP for data. Do not read [answers.json](answers.json) until all eight answers are complete.
2. For each case, capture UTC time and cumulative input, cached-input and output tokens immediately before the first search call and immediately after checking the retrieved JSON. Save the differences as case duration and token counts. Time the three MCP tools separately. Do not overlap cases or divide a turn-level token total among them. Cached input is part of input tokens; total tokens are input plus output.
3. Compare each answer with [answers.json](answers.json) and record `correct: true` or `correct: false`. Save the answer, dataset ID and artifact path. If retrieval fails, mark the answer incorrect.
4. Append the completed run to [results.json](results.json): run ID, model, reasoning level, harness, UTC start/finish and wall time, eight cases with their measurements and grades, summed token usage, and estimated cost. Sum case times for the table total; keep full suite wall time separate. Calculate cost from uncached input, cached input and output tokens using documented model rates and record the pricing source/date. If per-case token counters are unavailable, report that limitation and do not save a comparable run.
5. Run `python benchmarks/build_report.py` and `python benchmarks/build_report.py --check`. This generates [PERFORMANCE.md](PERFORMANCE.md) and the per-run summary and detail tables in [reports/](reports/).
